## 07. 色彩系统

### 7.1 视觉取舍

先确定一套可识别的主色与中性色。辅助色必须有明确角色，不为“丰富”堆砌颜色。解释色彩与产品定位的关系，避免把某种颜色心理效应描述成普遍科学结论。

分别确定品牌表达色与 UI 交互色：醒目的品牌颜色不一定适合白字按钮，必要时用不同的语义色阶。

### 7.2 三层结构

1. `primitive`：品牌、中性和状态色阶，如 50–950，按视觉需要调整，不强求每个色族拥有相同数量。
2. `semantic`：canvas、surface、raised、overlay、text、icon、border、action、focus、selection、status。
3. `component`：确有需求时建立 button、input、navigation 等组件角色，不给每个属性无意义地再包一层。

必须覆盖：浅色/深色、默认/悬浮/按下/选中/禁用、前景/背景/边框、链接/访问后链接（适用时）、成功/警告/危险/提示及其容器。

### 7.3 数值、映射与输出

可用感知色彩空间设计色阶，但必须实际检查色域、相邻层级与 sRGB 导出结果。输出 HEX/RGB 与 CSS 值由同一来源生成，不手工维护多套可能漂移的色值。

需要广色域输出时作为附加能力，并保留经过测试的 sRGB fallback。印刷转换另设流程，不把屏幕颜色的机械 CMYK 换算当作准确印色。

浅深主题是独立的语义映射，不直接反相。暗色模式注意文字灰阶、层次、发光感、状态色和叠层透明度。

生成可用配对矩阵：前景、背景、字号/字重条件、用途、对比度、是否合格。不要要求任意两种品牌色都满足文字对比度。矩阵用 `<skill>/scripts/contrast.py --matrix <pairs.json>` 计算，不手算。
